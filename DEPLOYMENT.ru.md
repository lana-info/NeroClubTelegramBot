# Запуск на сервере

Эта инструкция предназначена для владельца сервера и не требует менять
существующие проекты. Бот размещается отдельным проектом внутри
`/opt/bots-stack/nero-club`.

## Что уже есть

- исходный код и Docker Compose находятся в GitHub;
- база бота хранится в отдельной папке `data`;
- планировщик запускается вместе с backend;
- очереди Stripe и выдачи доступа проверяются раз в час;
- напоминания и проверка участников Telegram выполняются раз в сутки;
- секреты не должны попадать в GitHub, Google Sheets или логи.
- Для ручного режима установите `PAYMENT_SOURCE=sheet`. В этом режиме Stripe и
  PayPal отключены, а дата доступа берётся из Google Sheets.

## Что нужно сделать на сервере один раз

Эти действия выполняет администратор сервера. Они не останавливают другие
сервисы, но перед запуском нужно убедиться, что выбранный внутренний порт
свободен.

1. Создать каталог `/opt/bots-stack/nero-club` и получить в него
   согласованную ветку релиза из GitHub. Для автоматизации ручных платежей
   используйте `codex/sheet-payment-automation` до её слияния в основную
   ветку.
2. Создать закрытый файл
   `/opt/bots-stack/secrets/nero_club.env` с настройками из `.env.example`.
   Права файла: только владелец-системный администратор.
3. В `nero_club.env` указать Telegram-токен, ID чата и, если используется,
   ID специального канала (`TELEGRAM_CHANNEL_ID`), Telegram secret,
   Stripe API key, Stripe Price ID, Checkout return URLs и webhook secret,
   WordPress URL и shared secret,
   `ADMIN_API_TOKEN`, `APP_KEYS_ENCRYPTION_KEY`, ID администратора и ссылку
   оплаты.
4. Подключить два HTTPS-маршрута существующего reverse proxy:

   - `/webhooks/telegram` → backend бота;
   - `/webhooks/stripe` → backend бота.

   Порт Docker не открывается в Интернет: backend слушает только
   `127.0.0.1:18080`, а reverse proxy передаёт запросы локально.
5. В Stripe создать webhook для `/webhooks/stripe` и включить события
   подписки и оплаты, которые указаны в PRD.
6. В Telegram установить webhook на HTTPS-адрес `/webhooks/telegram` и
   один раз выполнить защищённую настройку меню команд. Эта настройка также
   включает события `message` и `chat_member`.

## Безопасный первый запуск

Сначала запускать с `DRY_RUN=true`. В этом режиме бот не удаляет участников
из чата и не отзывает доступ, но показывает, какие действия будут выполнены.

```sh
cd /opt/bots-stack/nero-club
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 bot-backend
curl http://127.0.0.1:18080/health
```

После проверки тестовым пользователем администратор меняет только
`DRY_RUN=false` в закрытом env-файле и пересоздаёт контейнеры. Другие проекты
и базы данных перезапускать нельзя.

## Как администратор будет работать

- Google Sheets — основная панель: пользователи, оплаты, доступ к сайту и
  ключи приложений;
- Telegram — меню для пользователя и обращения администратору;
- сервер — техническое место, которое запускается один раз и дальше работает
  автоматически.

## Что пока блокирует реальное включение

Без этих данных нельзя безопасно включать production:

- токен Telegram-бота и ID платного чата;
- Stripe webhook secret и рабочая ссылка оплаты;
- адрес и shared secret WordPress-плагина;
- HTTPS-адреса для Telegram и Stripe webhook;
- ID Telegram-аккаунта администратора.

Эти значения не нужно присылать в чат или коммитить. Их вводят непосредственно
в закрытый файл на сервере.
