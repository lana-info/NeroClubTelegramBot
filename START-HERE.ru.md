# Nero Club: простая инструкция для владельца

## Самое главное

Вам не нужно каждый день заходить на сервер. После настройки вы работаете
через Telegram и Google Таблицу.

- Google Таблица — панель управления пользователями, оплатами, доступом к
  сайту и ключами приложений.
- Telegram-бот — меню для пользователей и обращения администратору.
- Сервер — место, где всё работает автоматически.

На первом этапе ничего не удаляется автоматически: система запускается в
режиме проверки. Реальное удаление участников включается только после
отдельной проверки на тестовом чате.

## Если пользователи уже есть в чате

Не нужно удалять их и не нужно заставлять всех вступать заново.

Сначала в таблицу заносятся уже существующие пользователи:

1. Telegram ID или username;
2. имя и email, если нужен доступ к WordPress;
3. дата окончания оплаченной подписки;
4. отметка `whitelist`, если этому человеку нужно сохранить доступ вручную.

Важно: Telegram не даёт боту безопасно выгрузить полный список всех участников
закрытого чата. Поэтому неизвестных системе людей бот не трогает. Для начала
нужно связать пользователей с оплатой или добавить их вручную в таблицу.

После этого ежедневная проверка работает так:

- активная подписка — участник остаётся;
- закончилась подписка — в тестовом режиме бот только показывает, кого нужно
  было бы удалить;
- `whitelist` или ручное разрешение — доступ сохраняется;
- ручной запрет — доступ не восстанавливается автоматически.

## Как безопасно проверить систему

### Рекомендуемый вариант: отдельный тестовый бот и чат

Создайте в Telegram отдельного бота через `@BotFather`, например
`Nero Club Test Bot`. Создайте отдельную закрытую группу `Nero Club — Тест`.

В тестовую группу добавьте только:

- себя как владельца;
- тестовый Telegram-аккаунт;
- тестового бота администратором.

Не добавляйте в тестовую группу настоящих клиентов. Для тестового бота и
тестовой группы используются отдельные настройки и отдельная тестовая база.

Проверка проходит в таком порядке:

1. `DRY_RUN=true`: бот ничего не удаляет и не отключает.
2. Тестовый пользователь получает активную подписку.
3. Проверяется `/start`, статус, меню, ссылка оплаты и обращение админу.
4. Срок подписки меняется на прошедший.
5. Ежедневная проверка должна показать `would_remove`, но не удалить человека.
6. Проверяется whitelist: такой пользователь не должен попасть в список на
   удаление.
7. Только после письменного подтверждения владельца можно сделать один
   контрольный запуск с `DRY_RUN=false` в тестовом чате.
8. После успешного теста тестовый бот выключается, а production-бот
   настраивается отдельно.

### Что нельзя делать при проверке

- нельзя проверять удаление на настоящем платном чате;
- нельзя сначала ставить `DRY_RUN=false`;
- нельзя использовать рабочие Stripe и PayPal-секреты в тестовой системе;
- нельзя использовать настоящую базу WordPress без отдельного тестового
  пользователя;
- нельзя давать боту права администратора, если он ещё не проверен в тестовой
  группе.

## Telegram: где получить данные

### Токен бота

В Telegram откройте `@BotFather`:

1. `/newbot` — для нового бота;
2. задайте название;
3. задайте username, который заканчивается на `bot`;
4. скопируйте токен.

Токен нельзя присылать в чат или хранить в Google Таблице. Он вводится в
закрытую конфигурацию на сервере как `TELEGRAM_BOT_TOKEN`.

### Чат

Добавьте бота администратором в нужный чат и укажите в конфигурации
`TELEGRAM_CHAT_ID`. Для закрытой группы это обычно число, начинающееся с
`-100`. Точный ID получает администратор сервера во время настройки; вам не
нужно вычислять его вручную.

### Секрет webhook

`TELEGRAM_WEBHOOK_SECRET` — это не секрет от Telegram и не пароль BotFather.
Его создаёт сервер из длинной случайной строки. Пользователь не должен его
придумывать или присылать.

### ID администратора

`ADMIN_TELEGRAM_IDS` — числовой Telegram ID владельца. Он нужен, чтобы только
администратор мог отвечать на обращения и пользоваться админскими командами.
Этот ID можно определить во время первого запуска бота; username для этой
проверки недостаточно.

## Stripe: что нужно для первого рабочего варианта

Для MVP используем Stripe, а не PayPal: поддержка Stripe уже заложена в
проект.

1. В Stripe откройте `Payment links`.
2. Создайте товар с регулярной оплатой.
3. Скопируйте ссылку оплаты — это `PAYMENT_URL`.
4. В `Developers → Webhooks` добавьте адрес:

   `https://ВАШ-ДОМЕН/webhooks/stripe`

5. Скопируйте signing secret, начинающийся с `whsec_`.

Ссылку оплаты можно сообщить мне. Signing secret не присылайте: его вводят
на сервере как `STRIPE_WEBHOOK_SECRET`.

## PayPal: сейчас получать секреты не нужно

PayPal предусмотрен как следующий этап после стабилизации Stripe. В текущем
коде PayPal ещё не подключён, поэтому получение PayPal-секретов сейчас ничего
не даст и может запутать настройку.

Когда дойдём до PayPal:

1. открыть `developer.paypal.com`;
2. создать приложение в `Sandbox` для тестов;
3. получить `Client ID` и `Secret`;
4. создать подписочный план;
5. добавить webhook и получить webhook ID;
6. отдельно повторить настройку для `Live`.

Client Secret и webhook credentials нельзя хранить в таблице или отправлять в
чат. Их вводят в закрытый файл сервера. До этого этапа PayPal не настраивается.

## WordPress: что нужно сделать

1. Установить плагин из папки `wordpress-plugin`.
2. Создать длинную случайную фразу `NERO_CLUB_SHARED_SECRET`.
3. Добавить её в `wp-config.php`.
4. Ту же фразу сохранить в закрытой конфигурации бота как
   `WORDPRESS_SHARED_SECRET`.
5. Указать адрес сайта как `WORDPRESS_BASE_URL`.

Плагин умеет создать или активировать пользователя, выдать постоянный пароль
в личном Telegram и деактивировать доступ. Он не удаляет WordPress-пользователя
из базы и не выдаёт ему права администратора.

## Где хранятся настройки

На сервере создаётся закрытый файл:

`/opt/bots-stack/secrets/nero_club.env`

В нём находятся токены и секреты. Его нельзя:

- класть в GitHub;
- отправлять в Telegram;
- добавлять в Google Таблицу;
- пересылать мне сообщением;
- показывать на скриншоте.

В GitHub хранится только `.env.example` без настоящих значений.

## Что можете делать вы

Вы можете:

- добавлять пользователя в Google Таблицу;
- указывать дату окончания подписки;
- включать или снимать whitelist;
- вручную продлевать доступ;
- добавлять ключ приложения и дату его окончания;
- отвечать на обращения в Telegram;
- открыть Dashboard и увидеть состояние пользователей.

Вам не нужно:

- запускать Docker каждый день;
- редактировать Python-код;
- менять базу данных вручную;
- удалять пользователей из WordPress вручную;
- отправлять пароли в таблицу;
- настраивать PayPal до завершения Stripe.

## Что нужно передать мне

Безопасно передать можно:

- домен для webhook;
- название Telegram-чата;
- username Telegram-бота;
- ссылку Stripe Payment Link;
- адрес WordPress;
- желаемую длительность подписки;
- список тестовых Telegram-аккаунтов.

Нельзя передавать в чат:

- Telegram Bot Token;
- Stripe signing secret;
- PayPal Client Secret;
- WordPress shared secret;
- пароли пользователей;
- SSH-пароль или пароль сервера.

## Что ещё не включать

До завершения тестов нельзя включать автоматическое удаление в рабочем чате.
Кроме того, текущая версия ещё требует отдельной реализации события
«пользователь сам вышел из Telegram-чата» и полной интеграции PayPal. Пока это
не сделано, удаление WordPress-доступа выполняется по подтверждённому статусу
подписки или ручному действию, а не по одному факту выхода из чата.

## Короткий порядок запуска

1. Создать тестового Telegram-бота и тестовую группу.
2. Настроить Stripe в тестовом режиме.
3. Подготовить тестовый WordPress-пользователь.
4. Запустить бота с `DRY_RUN=true`.
5. Проверить меню, оплату, доступ к сайту, ключи и обращения.
6. Проверить список `would_remove`.
7. Выполнить один контрольный запуск удаления только в тестовой группе.
8. Перенести настройки на production и оставить удаление выключенным.
9. После ручного подтверждения включить production-режим.
