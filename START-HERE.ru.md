# Nero Club: простая инструкция для владельца

## Самое главное

Вам не нужно каждый день заходить на сервер. После настройки вы работаете
через Telegram и Google Таблицу.

- Google Таблица — панель управления пользователями, оплатами, доступом к
  сайту и ключами приложений.
- Telegram-бот — меню для пользователей и обращения администратору.
- Сервер — место, где всё работает автоматически.

Сейчас рекомендуется режим `PAYMENT_SOURCE=sheet`: Stripe и PayPal не
проверяются, а администратор вручную указывает оплату и дату окончания во
вкладке `Платежи`. Бот принимает решения о доступе только по синхронизированной
таблице. Когда понадобится автоматическая оплата, режим можно отдельно
переключить на Stripe.

Во вкладке `Настройки` можно независимо поставить `ВКЛ` или `ВЫКЛ` для удаления
из группы, удаления из канала, деактивации WordPress, выдачи доступа к сайту,
выдачи ключей и напоминаний. Например, можно выключить удаление, но оставить
выдачу ключей. Изменение применяется при ближайшей синхронизации таблицы. Уже
созданные операции остаются в очереди и выполнятся после включения функции.

Первоначальный пароль WordPress отправляется один раз в личном Telegram.
Пользователь должен сразу заменить его после входа. Пароль не хранится в боте
или таблице; повторную выдачу может запустить только администратор.

На первом этапе ничего не удаляется автоматически: система запускается в
режиме проверки. Реальное удаление участников включается только после
отдельной проверки на тестовом чате.

## Если пользователи уже есть в чате

Не нужно удалять их и не нужно заставлять всех вступать заново.

Сначала в таблицу заносятся уже существующие пользователи:

1. Telegram ID или username;
2. имя и email, если нужен доступ к WordPress;
3. дата окончания оплаченной подписки;
4. отметка `whitelist`, если этому человеку нужно сохранить доступ вручную.

Важно: Telegram не даёт боту безопасно выгрузить полный список всех участников
закрытого чата. Поэтому неизвестных системе людей бот не трогает. Для начала
нужно связать пользователей с оплатой или добавить их вручную в таблицу.

### Можно ли удалять из канала

Да. Telegram Bot API позволяет боту блокировать пользователя в обычной группе,
супергруппе и канале, если бот является администратором и имеет необходимые
права. В канале пользователь не сможет вернуться по ссылке, пока его сначала
не разблокировать.

Для первого теста лучше использовать закрытую супергруппу: там проще увидеть
вход, выход и результат блокировки. После этого можно отдельно проверить
закрытый канал одним тестовым аккаунтом. В канале пользователи не получают
меню внутри канала — меню и оплата работают в личном чате с ботом.

Бот не получает полный список подписчиков канала автоматически. Он проверяет
только пользователей, которые уже занесены в его базу или сначала написали
боту. Поэтому случайно удалить неизвестных подписчиков он не должен.

После этого ежедневная проверка работает так:

- активная подписка — участник остаётся;
- закончилась подписка — в тестовом режиме бот только показывает, кого нужно
  было бы удалить;
- `whitelist` или ручное разрешение — доступ сохраняется;
- ручной запрет — доступ не восстанавливается автоматически.

Перед реальным удалением бот сначала отправляет администратору предупреждение
в личный Telegram. В нём указаны username (если он есть), Telegram ID и место,
из которого пользователь будет удалён. Само удаление выполняется только при
следующей ежедневной проверке. Если оплату отметить в таблице между этими
проверками, предупреждение отменяется и пользователь остаётся.

## Как безопасно проверить систему

### Рекомендуемый вариант: отдельный тестовый бот и чат

Создайте в Telegram отдельного бота через `@BotFather`, например
`Nero Club Test Bot`. Создайте отдельную закрытую группу `Nero Club — Тест`
и, если проверяется канал, отдельный закрытый канал `Nero Club — Канал — Тест`.

В тестовую группу добавьте только:

- себя как владельца;
- тестовый Telegram-аккаунт;
- тестового бота администратором.

В тестовый канал добавьте того же тестового пользователя и бота
администратором с правом блокировать участников.

Не добавляйте в тестовую группу настоящих клиентов. Для тестового бота и
тестовой группы используются отдельные настройки и отдельная тестовая база.

Проверка проходит в таком порядке:

1. `DRY_RUN=true`: бот ничего не удаляет и не отключает.
2. Тестовый пользователь получает активную подписку.
3. Проверяется `/start`, статус, меню, ссылка оплаты и обращение админу.
4. Срок подписки меняется на прошедший.
5. Ежедневная проверка должна показать `would_remove`, но не удалить человека.
6. Проверяется whitelist: такой пользователь не должен попасть в список на
   удаление.
7. Только после письменного подтверждения владельца можно сделать один
   контрольный запуск с `DRY_RUN=false` в тестовом чате.
8. После успешного теста тестовый бот выключается, а production-бот
   настраивается отдельно.

### Что нельзя делать при проверке

- нельзя проверять удаление на настоящем платном чате;
- нельзя сначала ставить `DRY_RUN=false`;
- нельзя использовать рабочие Stripe и PayPal-секреты в тестовой системе;
- нельзя использовать настоящую базу WordPress без отдельного тестового
  пользователя;
- нельзя давать боту права администратора, если он ещё не проверен в тестовой
  группе.

### Полный тест по шагам

Попросите администратора сервера подготовить отдельную конфигурацию тестового
бота с `DRY_RUN=true`. В тестовой группе используйте два аккаунта: ваш
администраторский и тестовый пользователь.

1. Добавьте тестового бота в тестовую группу администратором с правами
   приглашать пользователей и блокировать участников.
2. Откройте тестового бота с тестового аккаунта и нажмите `/start`.
3. Убедитесь, что бот показывает меню, отвечает на «Статус подписки» и
   принимает обращение администратору.
4. В тестовой вкладке `Пользователи` найдите тестовый Telegram ID и поставьте
   дату подписки в будущем. Нажмите синхронизацию таблицы.
5. Проверьте, что статус стал `active`, а команда «Доступ к сайту» выдаёт
   логин и пароль только в личном Telegram.
6. Для проверки обычного выхода удалите тестового пользователя из группы
   обычным действием Telegram, не нажимая «Заблокировать». Ожидаемый результат:
   состояние `left`, задача `site.deactivate`, но фактического удаления в
   тестовом режиме нет.
7. Верните тестового пользователя в группу. Если подписка активна, ожидается
   задача `site.restore` после события вступления.
8. Для проверки истёкшей подписки поставьте дату в прошлом и запустите
   ежедневную сверку. При `DRY_RUN=true` результат должен показать
   `would_remove`, а пользователь должен остаться в группе.
9. В рабочем режиме первая ежедневная сверка после окончания доступа отправит
   вам предупреждение, но не удалит пользователя. Если оплата не отмечена,
   следующая ежедневная сверка удалит его из включённых группы и канала.
10. Только после этого временно установите `DRY_RUN=false` именно в тестовой
   конфигурации и повторите сверку. Бот должен сначала прислать вам предупреждение;
   повторный запуск на следующий день блокирует тестового пользователя в группе
   и в тестовом канале, но не владельца и не неизвестных участников.
11. Для проверки ручного бана заблокируйте тестового пользователя сами. После
    события `kicked` его WordPress-доступ отключается, а повторное вступление
    не возвращает его автоматически.
12. В таблице для этого пользователя выберите действие `restore_telegram`.
    В течение ближайшего запуска почасового worker-а бот разблокирует Telegram,
    создаст новую ссылку на вступление и отправит её пользователю. После
    вступления событие `member` поставит восстановление WordPress в очередь.
13. После проверки верните `DRY_RUN=true`. Рабочий чат и рабочие платежи до
    отдельного подтверждения не подключайте.

### Тест оплаты и персонального вступления

1. В тестовом Stripe создайте recurring Price и укажите его ID в тестовой
   конфигурации.
2. Убедитесь, что тестовый пользователь уже нажал `/start`.
3. Нажмите «Оплатить / продлить» и завершите оплату тестовой картой Stripe.
4. Дождитесь обработки `invoice.paid` или запустите Stripe worker вручную.
5. Пользователь должен получить персональную ссылку, действующую 15 минут.
6. Вступите по ссылке тестовым аккаунтом. Бот должен одобрить запрос.
7. С другого аккаунта та же ссылка должна быть отклонена.
8. Ссылка с истёкшим сроком должна быть отозвана hourly worker-ом.

Если какой-то шаг отличается, остановитесь на этом шаге и сохраните только
текст результата или скриншот без токенов. Не переходите к следующему шагу.

## Telegram: где получить данные

### Токен бота

В Telegram откройте `@BotFather`:

1. `/newbot` — для нового бота;
2. задайте название;
3. задайте username, который заканчивается на `bot`;
4. скопируйте токен.

Токен нельзя присылать в чат или хранить в Google Таблице. Он вводится в
закрытую конфигурацию на сервере как `TELEGRAM_BOT_TOKEN`.

### Чат

Добавьте бота администратором в нужный чат и укажите в конфигурации
`TELEGRAM_CHAT_ID`. Для закрытой группы это обычно число, начинающееся с
`-100`. Точный ID получает администратор сервера во время настройки; вам не
нужно вычислять его вручную.

Если доступ должен контролироваться ещё и в отдельном закрытом канале, его ID
указывается отдельно в `TELEGRAM_CHANNEL_ID`. Бот проверяет основной чат и
канал во время одной ежедневной проверки. При закончившейся подписке он
блокирует пользователя в обоих местах; при `DRY_RUN=true` только показывает
планируемое действие.

### Секрет webhook

`TELEGRAM_WEBHOOK_SECRET` — это не секрет от Telegram и не пароль BotFather.
Его создаёт сервер из длинной случайной строки. Пользователь не должен его
придумывать или присылать.

### ID администратора

`ADMIN_TELEGRAM_IDS` — числовой Telegram ID владельца. Он нужен, чтобы только
администратор мог отвечать на обращения и пользоваться админскими командами.
Этот ID можно определить во время первого запуска бота; username для этой
проверки недостаточно.

## Stripe: что нужно для первого рабочего варианта

Для MVP используем Stripe, а не PayPal: поддержка Stripe уже заложена в
проект.

1. В Stripe создайте recurring Price и сохраните его ID как `STRIPE_PRICE_ID`.
2. Создайте секретный API-ключ для сервера — `STRIPE_SECRET_KEY`.
3. Укажите `CHECKOUT_SUCCESS_URL` и `CHECKOUT_CANCEL_URL`.
4. В `Developers → Webhooks` добавьте адрес:

   `https://ВАШ-ДОМЕН/webhooks/stripe`

5. Включите события `checkout.session.completed`, `invoice.paid`,
   `invoice.payment_failed`, `customer.subscription.updated` и
   `customer.subscription.deleted`.
6. Скопируйте signing secret, начинающийся с `whsec_`.

Пользователь получает ссылку через кнопку «Оплатить / продлить» в боте.
Сессия создаётся с внутренним ID пользователя. После подтверждённого
`invoice.paid` бот создаёт персональную ссылку на вступление.

`STRIPE_SECRET_KEY` и signing secret не присылайте в чат: их вводят в закрытый
файл сервера как `STRIPE_SECRET_KEY` и `STRIPE_WEBHOOK_SECRET`.

## PayPal: сейчас получать секреты не нужно

PayPal предусмотрен как следующий этап после стабилизации Stripe. В текущем
коде PayPal ещё не подключён, поэтому получение PayPal-секретов сейчас ничего
не даст и может запутать настройку.

Когда дойдём до PayPal:

1. открыть `developer.paypal.com`;
2. создать приложение в `Sandbox` для тестов;
3. получить `Client ID` и `Secret`;
4. создать подписочный план;
5. добавить webhook и получить webhook ID;
6. отдельно повторить настройку для `Live`.

Client Secret и webhook credentials нельзя хранить в таблице или отправлять в
чат. Их вводят в закрытый файл сервера. До этого этапа PayPal не настраивается.

## WordPress: что нужно сделать

1. Установить плагин из папки `wordpress-plugin`.
2. Создать длинную случайную фразу `NERO_CLUB_SHARED_SECRET`.
3. Добавить её в `wp-config.php`.
4. Ту же фразу сохранить в закрытой конфигурации бота как
   `WORDPRESS_SHARED_SECRET`.
5. Указать адрес сайта как `WORDPRESS_BASE_URL`.

Плагин умеет создать или активировать пользователя, выдать постоянный пароль
в личном Telegram и деактивировать доступ. Он не удаляет WordPress-пользователя
из базы и не выдаёт ему права администратора.

## Где хранятся настройки

На сервере создаётся закрытый файл:

`/opt/bots-stack/secrets/nero_club.env`

В нём находятся токены и секреты. Его нельзя:

- класть в GitHub;
- отправлять в Telegram;
- добавлять в Google Таблицу;
- пересылать мне сообщением;
- показывать на скриншоте.

В GitHub хранится только `.env.example` без настоящих значений.

## Что можете делать вы

Вы можете:

- добавлять пользователя в Google Таблицу;
- указывать дату окончания подписки;
- включать или снимать whitelist;
- восстанавливать пользователя после административного бана действием
  `restore_telegram`;
- вручную продлевать доступ;
- добавлять ключ приложения и дату его окончания;
- отвечать на обращения в Telegram;
- открыть Dashboard и увидеть состояние пользователей.

Вам не нужно:

- запускать Docker каждый день;
- редактировать Python-код;
- менять базу данных вручную;
- удалять пользователей из WordPress вручную;
- отправлять пароли в таблицу;
- настраивать PayPal до завершения Stripe.

## Что нужно передать мне

Безопасно передать можно:

- домен для webhook;
- название Telegram-чата;
- username Telegram-бота;
- ссылку Stripe Payment Link;
- адрес WordPress;
- желаемую длительность подписки;
- список тестовых Telegram-аккаунтов.

Нельзя передавать в чат:

- Telegram Bot Token;
- Stripe signing secret;
- PayPal Client Secret;
- WordPress shared secret;
- пароли пользователей;
- SSH-пароль или пароль сервера.

## Что ещё не включать

До завершения тестов нельзя включать автоматическое удаление в рабочем чате.
Обработка события «пользователь сам вышел из Telegram-чата» уже добавлена, но
её нужно проверить на отдельном тестовом чате до production-включения. Полная
интеграция PayPal по-прежнему является следующим этапом; для первого запуска
используется Stripe.

## Короткий порядок запуска

1. Создать тестового Telegram-бота и тестовую группу.
2. Настроить Stripe в тестовом режиме.
3. Подготовить тестовый WordPress-пользователь.
4. Запустить бота с `DRY_RUN=true`.
5. Проверить меню, оплату, доступ к сайту, ключи и обращения.
6. Проверить список `would_remove`.
7. Проверить выход пользователя: WordPress должен попасть в очередь
   отключения.
8. Проверить административный бан: повторное вступление не должно вернуть
   доступ; восстановление выполняется через `restore_telegram`.
9. Выполнить один контрольный запуск удаления только в тестовой группе.
10. Перенести настройки на production и оставить удаление выключенным.
11. После ручного подтверждения включить production-режим.
