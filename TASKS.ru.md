## Task 6: Реализовать Telegram-доступ и invite-ссылки

Status: In progress

Goal:
Выдавать доступ только активным пользователям и удалять пользователей после окончания разрешённого периода.

Steps:
- настроить права бота-администратора;
- добавить персональную invite-ссылку через защищённый admin API и сверку участников в `DRY_RUN`;
- явно подписаться на `chat_member` и `chat_join_request` updates;
- создавать короткоживущие invite-ссылки с join request;
- одобрять запрос только для ожидаемого Telegram ID, отклонять чужой ID и отзывать ссылку после входа/таймаута;
- обрабатывать вход и выход пользователя идемпотентно;
- реализовать периодическую сверку;
- перед удалением отправлять администраторам предупреждение за одну ежедневную
  проверку; удалять только если доступ всё ещё не восстановлен;
- сверять известных пользователей через `getChatMember`, отдельно учитывать общий `getChatMemberCount` и расхождение с управляемым составом;
- реализовать dry-run/test mode;
- добавить повторную проверку перед удалением;
- удалять через `banChatMember`, а перед восстановлением выполнять `unbanChatMember` и выдавать новую ссылку.

Acceptance:
- [ ] Активный пользователь получает индивидуальную ссылку.
- [ ] Пересланная ссылка не даёт доступ другому Telegram ID.
- [ ] Просроченный пользователь не удаляется в test mode.
- [ ] В production пользователь удаляется только при подтверждённом `effective_access=denied`; whitelist и действующее ручное продление сохраняют доступ.
- [ ] После восстановления ранее удалённый пользователь может вступить повторно.
- [ ] Перед удалением администратор получает одно предупреждение с username,
  Telegram ID и местом удаления; восстановление оплаты отменяет удаление.
- [ ] Dashboard различает управляемых участников, общий счётчик и необъяснённую разницу, не заявляя полный список неизвестных участников.
- [ ] Ошибка Telegram не приводит к ложной блокировке аккаунта.

Verification:
- [ ] Тестовая группа с тестовыми аккаунтами.
- [ ] Сценарии входа, выхода, истечения и повторного доступа.

Current implementation note:

  `TELEGRAM_CHANNEL_ID`;

## Task 7: Создать WordPress-плагин синхронизации

Status: In progress

- добавить обязательные `permission_callback`, capability checks, валидацию входа, rate limit и idempotency key;
- связать существующего пользователя только по одноразовому токену из аутентифицированной WordPress-сессии либо по подтверждению, отправленному WordPress на уже сохранённый email аккаунта;
- найти/создать пользователя по подтверждённой связи, email или user ID;
- назначать только разрешённые роли;
- активировать и блокировать вход;
- снимать/возвращать платные права;
- при блокировке уничтожать все активные сессии пользователя;
- выдавать постоянный пароль только в личном сообщении Telegram, не записывая его в backend, логи или Sheets;
- записывать диагностические ответы.

Acceptance:
- [ ] Можно активировать существующий аккаунт.
- [ ] Можно заблокировать вход без удаления профиля.
- [ ] После блокировки ранее выданная WordPress-сессия больше не действует.
- [ ] Роль не может быть повышена до административной через таблицу.
- [ ] Совпадения email без подтверждения недостаточно для привязки существующего аккаунта.
- [ ] Пароль не хранится в открытом виде в backend, логах или Sheets; WordPress хранит только штатный хеш.
- [ ] Повтор операции безопасен.

Verification:
- [ ] Интеграционные тесты на тестовом WordPress.
- [ ] Проверка прав доступа, неверных credentials, отсутствующего capability и повторного idempotency key.
