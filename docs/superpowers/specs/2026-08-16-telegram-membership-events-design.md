# Решение: выход пользователя и бан администратора

## Статус

Утверждено владельцем проекта 2026-08-16; реализация выполняется по плану.

## Цель

Автоматически синхронизировать доступ к WordPress с фактическим состоянием
известного пользователя в Telegram, не затрагивая неизвестных людей и не
отменяя ручной бан администратора.

## Правила поведения

### Пользователь сам вышел

Если Telegram сообщает переход пользователя в состояние `left`, backend:

1. записывает событие в журнал;
2. помечает Telegram-доступ как отсутствующий;
3. ставит идемпотентную задачу на отключение WordPress-доступа;
4. отправляет задачу обычному почасовому worker-у.

Если пользователь снова вступил в чат, а подписка всё ещё действительна и нет
ручного запрета, доступ можно восстановить через существующий процесс
активации.

### Пользователь забанен администратором

Если Telegram сообщает состояние `kicked`, это считается ручным запретом:

1. WordPress-доступ отключается;
2. в базе сохраняется ручный запрет;
3. повторное вступление само по себе доступ не возвращает;
4. восстановление выполняется только отдельным действием администратора.

Бан, выполненный самим ботом из-за окончания подписки, не должен создавать
новую повторную задачу отключения.

### Защита от ошибок

- неизвестные Telegram ID игнорируются;
- `DRY_RUN=true` только записывает планируемое действие;
- повтор одного Telegram update не создаёт повторную операцию;
- ошибка WordPress остаётся в очереди для повторной обработки;
- whitelist не отменяет ручной `kicked`-запрет;
- администраторы и владелец чата не удаляются автоматической сверкой.

## Вебхук Telegram

В обработчик добавляется поддержка `chat_member` updates. При настройке webhook
в список `allowed_updates` добавляется `chat_member` наряду с обычными
сообщениями. Дополнительный порт и отдельный внешний сервис не нужны.

## Проверка

Обязательные тесты:

1. `left` создаёт отключение WordPress в `DRY_RUN`.
2. `kicked` создаёт ручной запрет.
3. повтор update не дублирует задачу.
4. неизвестный ID не меняет базу.
5. повторное вступление не отменяет ручной `kicked`-запрет.
6. действующая подписка восстанавливает доступ после обычного `left`.
7. ошибки WordPress обрабатываются worker-ом повторно.

## Последствия

Система будет реагировать почти сразу на переданное Telegram событие, а
почасовой worker останется резервной проверкой. Полная защита от неизвестных
участников сохраняется: Telegram не предоставляет боту полный список членов
закрытой группы, поэтому автоматические действия выполняются только для ID,
которые уже есть в базе.
