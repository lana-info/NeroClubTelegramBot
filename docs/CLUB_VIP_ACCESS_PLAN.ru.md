# Проектирование доступа Club VIP (2026-10-26)

Статус: проектирование, НЕ развернуто. Рабочая система без изменений.

## Правила
- Источник права: проверенное членство в Telegram чате (member/restricted/administrator/creator) И нет ручной деактивации или бана. Оплата и whitelist для этого права не важны.
- Состояние unknown/left/kicked не дает нового доступа до проверки Telegram; устаревшая строка Sheets не должна считаться доказательством.
- Отдельно купленные бессрочные лицензии сохраняют свой независимый сценарий и не отзываются из-за выхода из клуба.
- WordPress: создать/восстановить аккаунт и отправить логин с временным паролем пользователю в личные сообщения, не сохранять пароль в таблице/логах. При выходе/бане отключать лишь клубное право, не другое основание доступа.
- Приложения: источник списка — серверная конфигурация группы club vip. Все продукты группы положены активному участнику, включая новые продукты после включения в группу. При повторном запросе возвращать существующие лицензии.
- Генерация: отдельный защищенный service-to-service endpoint, не административная браузерная сессия. Идемпотентность по Telegram ID + product_id + entitlement club-vip, уникальность записи и сверка с лицензионным сервером после таймаута до повторной генерации. Ключ возвращать ровно один раз и сохранять зашифрованным в боте.
- Деактивация: остановить выдачу и по согласованной политике отзывать только клубные лицензии; не удалять независимые покупки. Повторная активация должна восстанавливать право без дубликатов.

## Обнаруженные ограничения
- В исходниках лицензионного сервера нет сущности групп и `club vip`; есть продукты и административный `/admin/licenses/generate`. Сначала нужна серверная модель group->products и сервисная выдача.
- Бот сейчас хранит назначенные ключи локально; не создаёт их на лицензионном сервере.
- Подписочный `effective_access` используется также для управления входом/удалением из Telegram: нельзя глобально заменить его на проверку членства без пересмотра всего потока.
- Старые тесты требуют независимой выдачи лицензий пользователям вне клуба, поэтому простая замена общего доступа недопустима.
- Резервная копия `/root/projects/NeroClubTelegramBot-backup-20261026T213206Z.tar.gz` охватывает исходный проект, но не рабочие данные `/opt/bots-stack`.

## Порядок реализации
1. Полный резервный снимок работающей БД и конфигурации с проверкой восстановления через уполномоченный доступ к `/opt/bots-stack`.
2. Явные статусы `club_entitlement` и `independent_license`, проверка реального членства, сохранение независимых лицензий.
3. Сервисный API и серверная группа `club vip`, уникальный ключ идемпотентности, тесты конкурентных запросов/таймаута.
4. Изменение выдачи ключей, доступа WordPress, обработчиков join/leave/ban и сверки; тесты оплативших/неоплативших/whitelist/deny/unknown/left/kicked/вне клуба.
5. Интеграционные тесты на тестовой БД и тестовых лицензиях. Затем отдельно согласованное развёртывание.
